# Support

Start with the affected project's README, documentation, and any local support
instructions. Use that project's documented support channel, or its issue tracker
when Issues is enabled. Use Discussions only if the project already offers them.
If no support channel is published, support may not be available.

## Useful help requests

Explain what you are trying to do, what happened, and what you expected. Include
the relevant version or commit, environment, a small example, and what you have
already tried. Link related documentation or issues where useful. Remove
credentials, personal data, and sensitive logs before sharing.

Support is best effort and depends on the maintainer's available time. Follow any
project-specific maintenance or supported-version statements; these shared
guidelines do not promise response times or support for every project or version.

## Suspected vulnerabilities

Do not post vulnerability details in public issues or PRs. Follow the affected
project's security policy and published private contact. On an affected public
repository, use **Security → Report a vulnerability** when that control is
available. Its availability depends on that repository's settings.

A shared `SECURITY.md` is pending an owner-selected, monitored private reporting
contact. There is currently no shared fallback private contact. If the affected
project offers neither private reporting nor a published private contact, avoid
public disclosure of technical details while a reporting route is unresolved.

## Problems with these shared defaults

For problems with these guidelines, forms, or templates, use
[this repository's Issues](https://github.com/Kian-Abdalkhani/.github/issues).
Report project-specific bugs and questions to the affected project.
